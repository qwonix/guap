# Ответы по алгоритмам и структурам данных

## Блок 1. Алгоритмы и их сложность

### 1. Что такое алгоритм и сложность алгоритма?

**Алгоритм** — конечная последовательность чётко определённых инструкций, предназначенная для решения некоторого класса задач за конечное время.

Основные свойства алгоритма:
- **Дискретность** — состоит из отдельных шагов
- **Детерминированность** — каждый шаг однозначно определён
- **Конечность** — завершается за конечное число шагов
- **Массовость** — применим к классу однотипных задач
- **Результативность** — даёт результат

**Сложность алгоритма** — количественная характеристика, описывающая объём ресурсов (время, память), необходимых для выполнения алгоритма в зависимости от размера входных данных n.

Различают:
- **Временную сложность** T(n) — количество элементарных операций
- **Пространственную сложность** S(n) — объём используемой памяти

*Пример:* линейный поиск в массиве из n элементов имеет временную сложность O(n), а бинарный поиск в отсортированном массиве — O(log n).

### 2. Какие существуют способы оценки сложности алгоритма?

Существует два основных подхода:

**1. Теоретический (априорный) анализ:**
- Анализ алгоритма без его выполнения
- Подсчёт количества операций как функции от размера входа
- Использование асимптотической нотации (O, Ω, Θ)
- *Преимущества:* не зависит от платформы, языка, компьютера
- *Недостатки:* даёт только асимптотику, скрывает константы

**2. Экспериментальный (апостериорный) анализ:**
- Реальное выполнение программы на конкретных данных
- Измерение времени работы и потребляемой памяти
- *Преимущества:* реальные показатели на конкретной системе
- *Недостатки:* зависит от языка, ОС, оборудования, компилятора

Также различают оценки по случаям:
- **Лучший случай** (Ω) — минимальное количество операций
- **Худший случай** (O) — максимальное количество операций
- **Средний случай** (Θ) — математическое ожидание

### 3. Что показывает теоретическая временная сложность?

Теоретическая временная сложность T(n) показывает, как зависит количество элементарных операций алгоритма от размера входных данных n.

Особенности:
- Измеряется не в секундах, а в количестве операций
- Не зависит от конкретного компьютера, языка, компилятора
- Описывает асимптотическое поведение алгоритма при росте n
- Выражается через стандартные функции: константные O(1), логарифмические O(log n), линейные O(n), линейно-логарифмические O(n log n), квадратичные O(n²), экспоненциальные O(2ⁿ) и др.

*Пример:* для сортировки пузырьком T(n) = O(n²). Это означает, что при удвоении n время работы вырастет приблизительно в 4 раза.

### 4. Что показывает теоретическая пространственная сложность?

Теоретическая пространственная сложность S(n) показывает, сколько **дополнительной** памяти потребляет алгоритм в зависимости от размера входа n.

Что учитывается:
- Память под вспомогательные структуры данных
- Память под рекурсивные вызовы (стек вызовов)
- Память под временные переменные

Обычно **не учитывается** память, занимаемая самими входными данными.

*Примеры:*
- Итеративный поиск максимума в массиве: O(1) — нужна одна переменная
- Рекурсивный обход дерева высоты h: O(h)
- Сортировка слиянием: O(n) — нужен дополнительный массив
- Сортировка на месте (in-place): O(1) или O(log n)

### 5. Какие факторы оказывают влияние на экспериментальную оценку временной сложности алгоритма?

**Аппаратные факторы:**
- Тактовая частота процессора
- Размер кэшей L1/L2/L3
- Скорость и объём оперативной памяти
- Архитектура процессора (число ядер, SIMD-инструкции)

**Программные факторы:**
- Язык программирования (компилируемый/интерпретируемый)
- Качество компилятора и уровень оптимизации
- Операционная система и её планировщик
- Параллельно работающие процессы

**Структура и характер входных данных:**
- Размер входа n
- Распределение данных (отсортированные, случайные, обратный порядок)
- Особые конфигурации (например, для быстрой сортировки на уже отсортированных данных — худший случай)

**Состояние системы:**
- Загрузка ЦП и ОЗУ другими процессами
- Состояние кэшей, страничный обмен
- Энергосбережение, троттлинг

Из-за этих факторов экспериментальные измерения необходимо повторять многократно и усреднять, желательно в фиксированных условиях.

### 6. Понятие O-символики

**O-нотация (Big O, «O большое»)** — асимптотическая верхняя оценка скорости роста функции.

**Формальное определение:** f(n) = O(g(n)), если существуют константы c > 0 и n₀ ≥ 0 такие, что для всех n ≥ n₀ выполняется 0 ≤ f(n) ≤ c·g(n).

Иначе говоря, g(n) — это верхняя граница роста функции f(n) с точностью до константного множителя для достаточно больших n.

**Другие асимптотические нотации:**
- **Ω(g(n))** — нижняя оценка: f(n) ≥ c·g(n)
- **Θ(g(n))** — точная оценка: c₁·g(n) ≤ f(n) ≤ c₂·g(n)
- **o(g(n))** — строгая верхняя оценка (f растёт строго медленнее g)
- **ω(g(n))** — строгая нижняя оценка

*Примеры:*
- 3n² + 5n + 7 = O(n²)
- log n = O(n)
- n! = O(nⁿ)
- 1000 = O(1)

### 7. Базовые принципы теоретической оценки временной сложности алгоритмов

1. **Подсчёт элементарных операций** — присваиваний, сравнений, арифметических действий, обращений к памяти.

2. **Правило сумм:** если алгоритм состоит из последовательных частей, общая сложность равна сумме (фактически максимуму) их сложностей: O(f(n)) + O(g(n)) = O(max(f, g)).

3. **Правило произведений (вложенности циклов):** при вложении конструкций сложности перемножаются. Цикл n раз внутри цикла n раз даёт O(n²).

4. **Анализ ветвлений:** в условных операторах берётся максимум по ветвям (в худшем случае).

5. **Отбрасывание констант:** в O-нотации игнорируются мультипликативные константы и слагаемые меньшего порядка. Например, 5n² + 3n + 7 → O(n²).

6. **Учёт худшего случая** по умолчанию — даёт гарантированную верхнюю границу для всех возможных входов.

7. **Рекуррентные соотношения** для рекурсивных алгоритмов решаются методом подстановки, дерева рекурсии или **мастер-теоремой**.

*Пример мастер-теоремы:* T(n) = 2T(n/2) + O(n) → T(n) = O(n log n) — сортировка слиянием.

### 8. Плюсы и минусы использования O-символики

**Плюсы:**
- Универсальность — не зависит от железа, языка, компилятора
- Простота сравнения алгоритмов на больших данных
- Скрывает несущественные детали, выделяя главное
- Позволяет классифицировать алгоритмы (полиномиальные, экспоненциальные)
- Удобна при проектировании и анализе алгоритмов

**Минусы:**
- Игнорирует константы: алгоритм с T(n) = 1000n может быть хуже T(n) = n² при малых n
- Показывает только асимптотику — при малых n картина может быть совершенно другой
- Не учитывает особенности железа (кэш-промахи, предсказание ветвлений)
- Худший случай может быть редким на практике (хеш-таблицы, быстрая сортировка)
- Не различает алгоритмы с одинаковой асимптотикой, но разной реальной скоростью

*Пример:* сортировка слиянием и быстрая сортировка обе имеют сложность O(n log n), но на практике быстрая сортировка часто быстрее за счёт лучшей кэш-локальности и меньших констант.

## Блок 2. Списки

### 1. Что такое список?

**Список** — линейная динамическая структура данных, состоящая из узлов (элементов), каждый из которых содержит данные и одну или несколько ссылок на другие узлы. Список позволяет хранить произвольное количество элементов и эффективно вставлять/удалять их.

**Отличия от массива:**
- Динамическое выделение памяти (под каждый элемент отдельно)
- Элементы могут быть разбросаны в памяти
- Доступ по индексу — за O(n), а не O(1)
- Вставка/удаление по итератору — за O(1) (а не O(n), как в массиве)

**Виды списков:**
- Линейный однонаправленный (singly linked)
- Линейный двунаправленный (doubly linked)
- Циклический однонаправленный
- Циклический двунаправленный

### 2. Основные характеристики линейного однонаправленного списка

Структура узла:
```c
struct Node {
    DataType data;
    Node* next;
};
```

**Характеристики:**
- Каждый узел хранит данные и указатель на **следующий** узел
- У последнего узла указатель next = NULL
- Доступ возможен только в одном направлении — от головы к хвосту
- Не имеет указателя на предыдущий элемент

**Операции:**
- Вставка в начало: O(1)
- Вставка в конец: O(n), или O(1) при наличии указателя на хвост
- Удаление узла по указателю: требуется знание предыдущего узла, O(n) в худшем случае
- Поиск элемента: O(n)
- Доступ по индексу: O(n)

**Память:** на каждый узел — данные + один указатель.

### 3. На какой элемент линейного однонаправленного списка необходимо обеспечивать позиционирование указателя?

Обязательно нужен указатель на **первый (головной) элемент** списка (head).

**Обоснование:**
- Обход возможен только в одном направлении (от начала к концу), поэтому потеря головного указателя означает потерю доступа ко всему списку
- Без головы невозможно начать обход и найти ни один элемент
- В однонаправленном списке нельзя «вернуться назад», поэтому без указателя на голову список становится недостижимым — возникает утечка памяти

Дополнительно часто хранят указатель на **хвост (tail)** для эффективной вставки в конец за O(1), но это не обязательно. **Голова — единственный обязательный указатель.**

### 4. Основные характеристики линейного двунаправленного списка

Структура узла:
```c
struct Node {
    DataType data;
    Node* next;
    Node* prev;
};
```

**Характеристики:**
- Каждый узел хранит данные и **два** указателя — на следующий и предыдущий узлы
- У головы prev = NULL, у хвоста next = NULL
- Возможен обход в обоих направлениях
- Удаление узла по его адресу — O(1) (есть прямой доступ к предыдущему)

**Операции:**
- Вставка/удаление в начало и конец: O(1) (при наличии указателей head/tail)
- Удаление узла по указателю: O(1)
- Поиск: O(n)

**Память:** на каждый узел — данные + два указателя (больше, чем у однонаправленного).

### 5. Сравнение линейного однонаправленного и линейного двунаправленного списка

| Критерий | Однонаправленный | Двунаправленный |
|---|---|---|
| Указателей в узле | 1 (next) | 2 (next, prev) |
| Память на узел | Меньше | Больше |
| Направление обхода | Только вперёд | В обе стороны |
| Удаление по указателю | O(n) — нужно найти prev | O(1) |
| Вставка перед узлом | O(n) | O(1) |
| Сложность реализации | Проще | Сложнее |
| Риск нарушения целостности | Меньше | Выше при ошибках |

**Когда что использовать:**
- **Однонаправленный** — когда обход всегда в одну сторону, экономия памяти важна (стек, простая очередь)
- **Двунаправленный** — когда нужны произвольные удаления, итераторы в обе стороны (LRU-кэш, дек, std::list в C++)

### 6. Основные характеристики циклического однонаправленного списка

**Характеристики:**
- Структура узла та же, что и у линейного однонаправленного
- Указатель next последнего узла указывает не на NULL, а **на первый узел**
- Образует «кольцо»
- Часто хранят указатель не на голову, а на хвост (доступ к голове через `tail.next` за O(1))

**Особенности:**
- Нет «конца» списка — нужно отслеживать обход
- Любой узел может рассматриваться как «начало»
- Удобен для задач с круговой природой: round-robin планирование, циклические буферы

**Операции:**
- Вставка в начало/конец: O(1) при указателе на хвост
- Поиск: O(n)
- Обход: требует условия остановки, иначе бесконечный цикл

### 7. Сравнение линейного и циклического однонаправленных списков

| Критерий | Линейный | Циклический |
|---|---|---|
| Конец списка | next = NULL | next последнего → head |
| Указатель «конца» | Явный (NULL) | Отсутствует |
| Условие остановки обхода | next == NULL | Возврат к стартовому узлу |
| Вставка в конец | O(n) или O(1) с tail | O(1) при указателе на tail |
| Применение | Универсальное | Round-robin, циклические буферы |
| Опасность | Меньше | Бесконечный цикл при ошибке обхода |

*Пример применения циклического списка:* планировщик задач с равными приоритетами; задача Иосифа Флавия.

### 8. Основные характеристики циклического двунаправленного списка

**Характеристики:**
- Каждый узел имеет указатели next и prev
- Образует двойное кольцо: head.prev = tail и tail.next = head
- Полностью симметричен — все узлы равноправны

**Операции:**
- Вставка/удаление в любую позицию по указателю: O(1)
- Обход в обоих направлениях
- Доступ к голове из хвоста и наоборот за O(1)

**Применение:**
- Реализация дека
- Очереди с приоритетом
- Различные планировщики
- Реализация LRU-кэшей
- Внутренняя реализация std::list в C++ (фактически — циклический двусвязный список с фиктивным узлом)

### 9. Сравнение линейного и циклического двунаправленных списков

| Критерий | Линейный двунаправленный | Циклический двунаправленный |
|---|---|---|
| Концы списка | head.prev = NULL, tail.next = NULL | head.prev = tail, tail.next = head |
| Доступ к хвосту от головы | O(n) без tail, O(1) с tail | O(1) — через head.prev |
| Условие конца обхода | NULL-указатель | Возврат к стартовому |
| Симметричность | Концы — особые случаи | Все узлы равноправны |
| Реализация операций | Больше специальных случаев | Единообразный код |
| Применение | Общее назначение | Циклические задачи, дек, планирование |

## Блок 3. Стек, очередь, дек

### 1. Что такое стек?

**Стек (stack)** — линейная структура данных, работающая по принципу **LIFO** (Last In, First Out — «последним пришёл, первым вышел»). Доступ предоставляется только к одному концу — **вершине стека (top)**.

**Основные операции:**
- `push(x)` — поместить элемент на вершину
- `pop()` — извлечь элемент с вершины
- `top()` / `peek()` — посмотреть верхний элемент без извлечения
- `isEmpty()` — проверка пустоты

Все операции выполняются за **O(1)**.

**Примеры применения:**
- Стек вызовов функций (call stack)
- Проверка скобочной последовательности
- Алгоритм обхода в глубину (DFS)
- Обратная польская запись (RPN), вычисление выражений
- Отмена действий (Undo)
- Преобразование инфиксной записи в постфиксную

### 2. Основные способы реализации стека. Сравнение

**1. На основе массива (статический стек):**
```c
int stack[MAX_SIZE];
int top = -1;

void push(int x) { stack[++top] = x; }
int pop() { return stack[top--]; }
```
- *Плюсы:* быстро (хорошая кэш-локальность), простая реализация, минимум служебной памяти.
- *Минусы:* фиксированный размер (переполнение), возможен резерв неиспользуемой памяти.

**2. На основе динамического массива (вектора):**
Аналогично статическому, но с возможностью увеличения (обычно удвоение размера при заполнении).
- *Плюсы:* динамический размер, амортизированная сложность push — O(1).
- *Минусы:* случайные перевыделения памяти, в худшем случае одна операция может стоить O(n).

**3. На основе односвязного списка:**
```c
struct Node { int data; Node* next; };
Node* top = nullptr;

void push(int x) { top = new Node{x, top}; }
```
- *Плюсы:* динамический размер, гарантированно O(1) на каждую операцию.
- *Минусы:* доп. память на указатели, хуже кэш-локальность, накладные расходы на аллокации.

**Сравнение:**

| Критерий | Массив | Динамический массив | Связный список |
|---|---|---|---|
| Размер | Фиксированный | Динамический | Динамический |
| push | O(1) | O(1) амортизированно | O(1) |
| Кэш-локальность | Отличная | Хорошая | Плохая |
| Доп. память | Нет | На запас | На указатели |

### 3. Что такое очередь?

**Очередь (queue)** — линейная структура данных, работающая по принципу **FIFO** (First In, First Out — «первым пришёл, первым вышел»).

Доступ к двум концам:
- **Конец очереди (rear/tail)** — туда добавляются элементы (`enqueue`)
- **Начало очереди (front/head)** — оттуда извлекаются элементы (`dequeue`)

**Основные операции:**
- `enqueue(x)` — добавить в конец
- `dequeue()` — извлечь из начала
- `front()` — посмотреть первый элемент
- `isEmpty()` — проверка пустоты

Все операции — **O(1)**.

**Применение:**
- Планирование задач в ОС
- Обход в ширину (BFS)
- Буферизация потоков данных
- Очереди печати
- Обработка событий и сообщений

### 4. Основные способы реализации очереди. Сравнение

**1. На основе кольцевого буфера (circular buffer):**
```c
int queue[N];
int head = 0, tail = 0, size = 0;

void enqueue(int x) {
    queue[tail] = x;
    tail = (tail + 1) % N;
    size++;
}
int dequeue() {
    int x = queue[head];
    head = (head + 1) % N;
    size--;
    return x;
}
```
- *Плюсы:* O(1) на операцию, хорошая кэш-локальность, используется вся выделенная память.
- *Минусы:* фиксированный размер, чуть сложнее логика индексации.

**2. На основе двух стеков:**
`enqueue` пишет в стек 1, `dequeue` берёт из стека 2. Когда стек 2 пуст, всё перекладывается из 1 в 2.
- *Плюсы:* использует готовую структуру.
- *Минусы:* амортизированная O(1), отдельные операции могут быть O(n).

**3. На основе односвязного списка:**
Хранятся два указателя — head и tail. `enqueue` идёт в tail, `dequeue` — из head.
- *Плюсы:* динамический размер, гарантированно O(1).
- *Минусы:* накладные расходы на узлы, хуже локальность.

**4. На основе двусвязного списка:**
То же, но с обратными указателями. Преимуществ для классической очереди не даёт, но удобно для дека.

| Реализация | Размер | Сложность | Память |
|---|---|---|---|
| Кольцевой буфер | Фикс. | O(1) | Эффективная |
| Связный список | Динам. | O(1) | Накладные расходы |
| Два стека | Динам. | O(1) аморт. | Худший случай — O(n) |

### 5. Что такое дек?

**Дек (deque, double-ended queue)** — линейная структура данных, обобщающая стек и очередь: позволяет добавлять и удалять элементы с **обоих концов** за O(1).

**Основные операции:**
- `push_front(x)`, `pop_front()` — операции с началом
- `push_back(x)`, `pop_back()` — операции с концом
- `front()`, `back()` — просмотр краёв

**Способы реализации:**
- Двусвязный список (наиболее естественно)
- Кольцевой буфер с двумя указателями
- Блочный массив (как std::deque в C++ — массив указателей на блоки)

**Применение:**
- Алгоритм «скользящего максимума» (sliding window maximum)
- Реализация и стека, и очереди одновременно
- Проверка палиндромов
- Алгоритмы поиска (A*, двунаправленный поиск)

### 6. В каких случаях целесообразно применять стек, а в каких очередь?

**Стек (LIFO) — когда:**
- Нужен возврат «назад» по истории (Undo/Redo)
- Обход в глубину (DFS) — естественная рекурсия
- Анализ вложенных конструкций (скобки, теги, парсеры)
- Вычисление выражений (постфиксная запись)
- Преобразование рекурсии в итерацию
- Имитация стека вызовов функций

**Очередь (FIFO) — когда:**
- Важен порядок поступления элементов
- Планирование задач (CPU scheduling, очередь печати)
- Обход в ширину (BFS) — поиск кратчайшего пути в невзвешенном графе
- Буферизация потоков данных (производитель-потребитель)
- Обработка событий, сообщений
- Кэш с FIFO-стратегией

**Правило:** если важна **структура вложенности** (последнее активное действие) — выбираем стек; если важна **временна́я последовательность** обработки — очередь.

### 7. Достоинства и недостатки статических и динамических структур данных

**Статические структуры (массивы, статические стеки/очереди):**

*Плюсы:*
- Высокая скорость доступа O(1) по индексу
- Отличная кэш-локальность
- Минимум накладных расходов на память
- Простая и предсказуемая реализация
- Память выделяется один раз

*Минусы:*
- Фиксированный размер (нужно знать заранее)
- Возможны переполнение или неиспользуемая память
- Дорогая вставка/удаление в середине — O(n)
- Негибкие при росте данных

**Динамические структуры (списки, динамические массивы):**

*Плюсы:*
- Размер подстраивается под данные
- Эффективная вставка/удаление в произвольных местах
- Нет переполнения (пока есть память)
- Гибкость структуры

*Минусы:*
- Накладные расходы на указатели и метаданные
- Хуже кэш-локальность → медленнее на современных процессорах
- Затраты на выделение/освобождение памяти
- Фрагментация памяти
- O(n) для доступа по индексу (для связных)
- Сложнее реализация и отладка

На практике часто предпочитают **динамические массивы** (std::vector, ArrayList) — они объединяют преимущества обоих подходов.

## Блок 4. Хеширование

### 1. Что такое хеш-функция?

**Хеш-функция** — функция h(k), отображающая ключи k из большого (потенциально бесконечного) множества K в небольшой диапазон целых чисел [0, m-1], которые используются как индексы в хеш-таблице:

> h: K → {0, 1, ..., m-1}

**Цель:** обеспечить быстрый (в среднем O(1)) доступ к данным по ключу.

*Примеры:*
- Метод деления: h(k) = k mod m
- Метод умножения: h(k) = ⌊m·(k·A mod 1)⌋, где 0 < A < 1
- Хеширование строк (полиномиальное): h(s) = (s[0] + s[1]·p + s[2]·p² + ...) mod m, где p — простое число

### 2. Каким свойством обладает идеальная хеш-функция?

**Идеальная (совершенная) хеш-функция:**

1. **Биективность** на используемом множестве ключей — каждому ключу соответствует уникальный индекс, **полное отсутствие коллизий**.

2. **Равномерное распределение** — для случайного ключа из K вероятность попасть в любую ячейку одинакова.

3. **Минимальная совершенная хеш-функция** — отображает n ключей в точно n значений (нет пустых ячеек).

На практике идеальная хеш-функция возможна только при заранее известном фиксированном множестве ключей. Для произвольных ключей построить её невозможно — по **принципу Дирихле** коллизии неизбежны (поскольку |K| ≫ m).

### 3. Какие требования предъявляются к хеш-функциям?

1. **Детерминированность** — одинаковые ключи дают одинаковые хеши.

2. **Равномерность распределения** — минимизирует коллизии, равномерное распределение по корзинам.

3. **Скорость вычисления** — O(1) для чисел или O(длины ключа) для строк.

4. **Лавинный эффект** — малое изменение ключа сильно меняет хеш (особенно важно для криптографических функций).

5. **Использование всех битов ключа** — иначе теряется информация и возрастает число коллизий.

6. **Зависимость от типа ключа:**
   - Для чисел — учитывать диапазон
   - Для строк — учитывать все символы и их позиции
   - Для составных типов — комбинировать хеши полей

7. **Размер таблицы m часто берут простым числом** (для метода деления) — это уменьшает корреляции с распределением ключей.

### 4. Что такое открытое хеширование?

**Открытое хеширование (метод цепочек, chaining)** — стратегия разрешения коллизий, при которой каждой ячейке хеш-таблицы соответствует **связный список** (или другая структура) элементов с одинаковым хешем.

Структура:
```
[0] → A → B → C
[1] → 
[2] → D
[3] → E → F
```

**Операции:**
- **Insert(k):** вычислить i = h(k), добавить в список ячейки i
- **Search(k):** вычислить i = h(k), искать в списке ячейки i линейно
- **Delete(k):** найти и удалить из списка

**Сложность:**
- Средняя — O(1 + α), где α = n/m — коэффициент загрузки
- Худшая — O(n) (если все ключи попали в одну корзину)

*Плюсы:* простая реализация; не требует перехеширования при заполнении; допускает коэффициент загрузки α > 1; удаление просто.

*Минусы:* дополнительная память на указатели; плохая кэш-локальность; накладные расходы на аллокации.

### 5. Что такое закрытое хеширование?

**Закрытое хеширование (метод открытой адресации, open addressing)** — все элементы хранятся в самой таблице (без вспомогательных структур). При коллизии ищется альтернативная пустая ячейка по определённому правилу — повторному хешированию.

**Операции:**
- **Insert(k):** пробовать h(k, i) при i = 0, 1, 2, ... пока не найдётся пустая ячейка
- **Search(k):** пробовать h(k, i) пока не найдётся k или пустая ячейка
- **Delete(k):** ячейка помечается специальным флагом «удалено» (см. ниже)

Коэффициент загрузки α ≤ 1 (таблица не может содержать больше элементов, чем у неё ячеек).

**Методы повторного хеширования:**
- Линейное опробование
- Квадратичное опробование
- Двойное хеширование

*Плюсы:* лучшая кэш-локальность (всё в одном массиве); меньше памяти (нет указателей); нет затрат на аллокации.

*Минусы:* деградация при α → 1; сложное удаление; требуется перехеширование (resize) при заполнении.

### 6. Каким образом осуществляется удаление данных при закрытом хешировании и почему?

**Прямое физическое удаление невозможно** — оно сломает поиск других элементов.

*Пример проблемы:* пусть элементы A, B, C попали в одну цепочку опробования (одинаковый стартовый хеш). Если удалить B, просто пометив ячейку пустой, то при поиске C алгоритм встретит пустую ячейку и **прекратит поиск**, не найдя C, который реально существует.

**Решение — логическое удаление с маркером:**

Вводится третье состояние ячейки:
- **EMPTY** — никогда не использовалась → поиск останавливается
- **OCCUPIED** — содержит элемент → поиск продолжается
- **DELETED** — помечена удалённой → поиск **продолжается**, но вставка может использовать эту ячейку

При поиске мы пропускаем DELETED-ячейки. При вставке можем использовать первую встреченную DELETED-ячейку (повторно использовать освободившуюся память).

*Недостаток:* со временем накапливаются «надгробия» (tombstones), увеличивая длину цепочек поиска. Требуется периодическое перехеширование (rehash) для очистки.

### 7. Какие методы повторного хеширования существуют? Сравнение

**1. Линейное опробование (linear probing):**
> h(k, i) = (h(k) + i) mod m

Проверяем ячейки h(k), h(k)+1, h(k)+2, ...

- *Плюсы:* простота, отличная кэш-локальность.
- *Минусы:* **первичная кластеризация** — образуются длинные сплошные цепочки занятых ячеек.

**2. Квадратичное опробование (quadratic probing):**
> h(k, i) = (h(k) + c₁·i + c₂·i²) mod m

Чаще: h(k, i) = (h(k) + i²) mod m

- *Плюсы:* уменьшает первичную кластеризацию.
- *Минусы:* **вторичная кластеризация** — два ключа с одинаковым h(k) идут по одной траектории; не все ячейки могут быть опробованы — нужны специальные значения m и констант.

**3. Двойное хеширование (double hashing):**
> h(k, i) = (h₁(k) + i·h₂(k)) mod m

Шаг зависит от **второй** хеш-функции h₂(k).

- *Плюсы:* устраняет и первичную, и вторичную кластеризации, наилучшее распределение.
- *Минусы:* вычисление двух хешей, требует gcd(h₂(k), m) = 1.

**Сравнение:**

| Метод | Кэш-локальность | Кластеризация | Скорость | Сложность |
|---|---|---|---|---|
| Линейное | Отличная | Первичная (сильная) | Быстрый при малых α | Простой |
| Квадратичное | Хорошая | Вторичная | Средняя | Средний |
| Двойное | Хуже | Минимальная | Лучшее распределение | Сложнее |

### 8. Каким образом определяется адрес при линейном опробовании?

При линейном опробовании последовательность адресов:
> h(k, i) = (h(k) + i) mod m, для i = 0, 1, 2, ..., m-1

То есть проверяются ячейки: h(k), h(k)+1, h(k)+2, ..., с переходом по кругу.

*Пример (m = 7, h(k) = k mod 7):*
- Вставка 14: h(14) = 0, ячейка 0 пуста → 14 в ячейку 0
- Вставка 21: h(21) = 0, ячейка 0 занята → пробуем 1, пуста → 21 в ячейку 1
- Вставка 28: h(28) = 0, ячейки 0, 1 заняты → пробуем 2 → 28 в ячейку 2

Здесь хорошо видно образование первичного кластера в ячейках 0-1-2.

### 9. Каким образом определяется адрес при квадратичном опробовании?

> h(k, i) = (h(k) + c₁·i + c₂·i²) mod m, для i = 0, 1, 2, ...

Часто используется упрощённый вариант: h(k, i) = (h(k) + i²) mod m. Шаги увеличиваются квадратично: 0, 1, 4, 9, 16, ...

*Пример (m = 11, h(k) = k mod 11, h(k, i) = (h(k) + i²) mod 11):*
- Вставка 26: h(26) = 4, ячейка 4 пуста → 26 в 4
- Вставка 37: h(37) = 4, ячейка 4 занята; i=1: (4+1) mod 11 = 5 → 37 в 5
- Вставка 48: h(48) = 4; i=1: 5 занята; i=2: (4+4) mod 11 = 8 → 48 в 8

**Важно:** при произвольных m не все ячейки могут быть опробованы. Чтобы покрыть все ячейки, обычно требуется: m — простое число, и α < 1/2, либо специальный подбор c₁ и c₂.

### 10. Каким образом определяется адрес при двойном хешировании?

> h(k, i) = (h₁(k) + i·h₂(k)) mod m, для i = 0, 1, 2, ...

Шаг повторного хеширования сам зависит от ключа (через h₂).

**Требования:**
- h₂(k) ≠ 0 для любого k
- gcd(h₂(k), m) = 1 — обычно m простое или h₂(k) всегда нечётное при m = 2^p

**Типичные функции:**
- h₁(k) = k mod m
- h₂(k) = 1 + (k mod (m - 2))
- Либо h₂(k) = R - (k mod R), где R < m — простое

*Пример (m = 13, h₁(k) = k mod 13, h₂(k) = 1 + k mod 11):*
- Вставка 14: h₁(14) = 1, ячейка 1 пуста → 14 в 1
- Вставка 27: h₁(27) = 1, занято; h₂(27) = 1 + 5 = 6; i=1: (1+6) mod 13 = 7 → 27 в 7
- Вставка 40: h₁(40) = 1, занято; h₂(40) = 1 + 7 = 8; i=1: (1+8) mod 13 = 9 → 40 в 9

Заметим: ключи с одинаковым h₁, но разным h₂ идут по разным траекториям — нет вторичной кластеризации.

### 11. Для чего используется алгоритм хеширования? Плюсы и минусы

**Применение:**

1. **Хеш-таблицы** — ассоциативные массивы (словари, множества) с O(1) доступом: std::unordered_map в C++, dict в Python, HashMap в Java.

2. **Криптография:**
   - Хранение паролей (хешируются, не сохраняются открыто)
   - Цифровые подписи
   - Контроль целостности данных (MD5, SHA-1, SHA-256)

3. **Контрольные суммы** — проверка целостности файлов при передаче.

4. **Системы контроля версий** — Git использует SHA-1 для идентификации коммитов.

5. **Дедупликация данных** — поиск дубликатов файлов.

6. **Распределённые системы:**
   - Consistent hashing для распределения нагрузки
   - Распределённые хеш-таблицы (DHT) — BitTorrent, IPFS

7. **Структуры с фильтрацией** — фильтры Блума, Cuckoo-фильтры.

8. **Кэширование** — формирование ключей кэша.

**Плюсы:**
- Среднее O(1) для основных операций — очень быстро
- Простота использования
- Универсальность (работает с любыми типами при наличии хеш-функции)
- Не требует упорядочивания ключей

**Минусы:**
- Худшая сложность O(n) при плохой хеш-функции или атаках
- Высокое потребление памяти (нужен запас m > n)
- Нет упорядоченности ключей (для упорядочения нужны деревья)
- Деградация при высоком коэффициенте загрузки
- Требует перехеширования при росте
- Хеш-функции могут быть уязвимы для атак (hash flooding)
- Качество работы сильно зависит от качества хеш-функции

## Блок 5. Сортировка

### 1. Что такое сортировка?

**Сортировка** — процесс упорядочивания элементов некоторого множества (массива, списка) по заданному критерию: возрастанию, убыванию или согласно некоторому отношению порядка.

Формально: дана последовательность a₁, a₂, ..., aₙ. Требуется получить её перестановку a'₁, a'₂, ..., a'ₙ такую, что a'₁ ≤ a'₂ ≤ ... ≤ a'ₙ (для возрастания).

**Классификация:**
- По устойчивости (стабильности): сохраняется ли исходный порядок одинаковых элементов
- По месту работы (in-place / out-of-place): использует ли алгоритм дополнительную память
- По расположению данных (внутренняя / внешняя)
- По сложности (O(n²), O(n log n), O(n))
- По принципу: сортировка сравнением, сортировка распределением, комбинированные

### 2. Виды сортировки по местоположению сортируемых данных

**Внутренняя сортировка:**
- Все данные помещаются в **оперативную память** (ОЗУ)
- Доступ к любому элементу за O(1) — произвольный доступ
- Алгоритмы: пузырьковая, выбором, вставками, быстрая, слиянием (in-place), пирамидальная и т.д.
- Применяется для умеренных объёмов данных

**Внешняя сортировка:**
- Данные не помещаются в ОЗУ, хранятся на **внешних носителях** (диск, лента)
- Доступ преимущественно **последовательный** (или с дорогим произвольным)
- Главная проблема — минимизация обращений к внешней памяти (на порядки медленнее ОЗУ)
- Алгоритмы: многопутевое слияние (multiway merge), polyphase merge sort, распределение по runs

**Особенности внешней сортировки:**
1. Разделение на блоки (runs), помещающиеся в ОЗУ
2. Сортировка каждого блока внутренней сортировкой
3. Многопроходное слияние блоков
4. Использование буферов для эффективного ввода-вывода

*Пример:* сортировка файла 100 ГБ при ОЗУ 4 ГБ требует внешней сортировки в обязательном порядке.

### 3. Временная и пространственная сложность алгоритмов внутренней сортировки

| Алгоритм | Лучший | Средний | Худший | Память | Стабильность |
|---|---|---|---|---|---|
| Пузырьковая | O(n) | O(n²) | O(n²) | O(1) | Да |
| Выбором | O(n²) | O(n²) | O(n²) | O(1) | Нет |
| Вставками | O(n) | O(n²) | O(n²) | O(1) | Да |
| Шелла | O(n log n) | ≈O(n^1.33) | O(n²) | O(1) | Нет |
| Быстрая (QuickSort) | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет |
| Слиянием (MergeSort) | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |
| Пирамидальная (HeapSort) | O(n log n) | O(n log n) | O(n log n) | O(1) | Нет |
| Подсчётом (Counting) | O(n+k) | O(n+k) | O(n+k) | O(k) | Да |
| Поразрядная (Radix) | O(d(n+k)) | O(d(n+k)) | O(d(n+k)) | O(n+k) | Да |

**Теоретический предел** для сортировок сравнениями: Ω(n log n) — доказано через деревья решений.

**Сортировки распределением** (counting, radix, bucket) могут работать за O(n), но требуют ограничений на ключи.

### 4. Почему теоретическая оценка быстродействия алгоритма быстрой сортировки носит вероятностный характер?

Быстрая сортировка (QuickSort) работает так:
1. Выбирается опорный элемент (pivot)
2. Массив разбивается на части: меньше pivot и больше pivot
3. Рекурсивно сортируются обе части

Сложность зависит от **сбалансированности разбиения**:

- **Лучший случай** (pivot всегда медиана): T(n) = 2T(n/2) + O(n) → **O(n log n)**
- **Худший случай** (pivot всегда минимум или максимум, например, на уже отсортированном массиве при выборе первого элемента): T(n) = T(n-1) + O(n) → **O(n²)**
- **Средний случай** (при случайном выборе pivot): **O(n log n)** в математическом ожидании, но с определённой дисперсией

**Почему оценка вероятностная:**
- Качество работы зависит от **распределения входных данных** и **стратегии выбора pivot**
- При **случайном выборе** pivot вероятность каждого исхода соответствует распределению вероятностей
- Худший случай возможен, но его вероятность мала на случайных данных
- Математически: E[T(n)] = O(n log n), но конкретный запуск может быть и быстрее, и медленнее

**Способы избежать худшего случая:**
- Случайный выбор pivot (Randomized QuickSort)
- Метод медианы трёх (median of three)
- Метод медианы медиан (детерминированный, гарантирует O(n log n), но с большой константой)
- Переход на другой алгоритм при большой глубине рекурсии (Introsort)

Таким образом, гарантировать O(n log n) для произвольных данных без вероятностной природы невозможно — отсюда и вероятностный характер оценки.

### 5. В чём отличительная особенность алгоритма сортировки распределением и в чём основной недостаток вырожденной сортировки распределением?

**Сортировка распределением** не использует сравнение элементов. Вместо этого:
- Определяется диапазон возможных значений
- Создаются «корзины» (buckets) для значений
- Каждый элемент помещается в свою корзину по ключу
- Корзины обходятся в порядке возрастания → отсортированная последовательность

*Примеры:*
- **Counting sort (подсчётом)** — для целых чисел из небольшого диапазона
- **Radix sort (поразрядная)** — сортировка по разрядам
- **Bucket sort (карманная)** — для равномерно распределённых чисел

**Отличительная особенность:**
- Работа **без сравнений** ключей
- Возможна сложность O(n) — преодоление барьера Ω(n log n)
- Используется структура самих ключей (числовая природа, разряды)

**Вырожденная сортировка распределением** — counting sort в простейшем виде, когда для каждого возможного значения ключа выделяется отдельная корзина.

**Основной недостаток:**
- Требует **O(k)** дополнительной памяти, где k — размер диапазона ключей
- Эффективна только при **k = O(n)**
- При большом диапазоне значений (например, 32-битные числа, k ≈ 4·10⁹) требуется огромная память, что делает алгоритм неприменимым
- Не работает с нечисловыми ключами без специальной кодировки
- Не работает с вещественными числами в общем случае

*Пример:* отсортировать массив из 1000 элементов со значениями от 0 до 10⁹ — вырожденная сортировка распределением потребует массив из 10⁹ ячеек, что неприемлемо.

**Решение:** поразрядная сортировка (radix sort) разбивает ключи на разряды и применяет counting sort к каждому разряду, снижая требования к памяти до O(n + b), где b — основание системы счисления (например, 10 или 256).

### 6. Что такое временная и пространственная сложность алгоритма?

**Временная сложность T(n)** — функция, описывающая количество элементарных операций, выполняемых алгоритмом при размере входных данных n.

Под элементарными операциями обычно понимают:
- Арифметические операции (+, -, *, /)
- Сравнения
- Присваивания
- Обращения к памяти

Различают:
- T_best(n) — лучший случай (Ω)
- T_avg(n) — средний случай (Θ)
- T_worst(n) — худший случай (O)

**Пространственная сложность S(n)** — функция, описывающая объём дополнительной памяти, необходимой алгоритму помимо входных данных.

Включает:
- Память под вспомогательные переменные и структуры
- Память под стек рекурсии
- Память под буферы

*Обычно не включает:*
- Память под сами входные данные
- Память под выходные данные (когда они вынуждены)

*Примеры:*
- Бинарный поиск: T(n) = O(log n), S(n) = O(1)
- Сортировка слиянием: T(n) = O(n log n), S(n) = O(n)
- Быстрая сортировка: T(n) = O(n log n) в среднем, S(n) = O(log n) на стек рекурсии

### 7. Что такое теоретическая временная и теоретическая пространственная сложность алгоритма?

**Теоретическая временная сложность** — это **математическая** оценка количества элементарных операций алгоритма как функции от размера входа n.

Особенности:
- Не зависит от конкретного компьютера, языка программирования, ОС
- Получается аналитически из текста алгоритма
- Выражается в асимптотической нотации (O, Ω, Θ)
- Описывает поведение при n → ∞

*Например*, для двух вложенных циклов по n: T(n) = O(n²) — независимо от того, выполняется ли это на суперкомпьютере или на калькуляторе.

**Теоретическая пространственная сложность** — это математическая оценка объёма дополнительной памяти, требуемой алгоритму.

Особенности:
- Измеряется в единицах памяти (ячейки, биты, байты) или асимптотически
- Зависит от размера входа n
- Не учитывает реальный объём байт в конкретной реализации

В противоположность теоретическим, **экспериментальные оценки**:
- Измеряются в реальных секундах и байтах
- Зависят от железа, языка, нагрузки
- Могут различаться от запуска к запуску

Теоретические оценки даются раз и навсегда, экспериментальные — для конкретной среды.

## Блок 6. Деревья

### 1. Что такое дерево? Что такое высота и степень дерева?

**Дерево** — связный ациклический ориентированный (или неориентированный) граф. В контексте структур данных — иерархическая структура из узлов, соединённых рёбрами, без циклов.

**Свойства:**
- Один выделенный узел — **корень (root)**
- Каждый узел, кроме корня, имеет ровно одного **родителя**
- Узел может иметь несколько **потомков (детей)**
- Узлы без потомков — **листья (leaves)**
- Узел с потомками — **внутренний узел**

**Связанные понятия:**
- **Поддерево** — узел вместе со всеми его потомками
- **Уровень узла** — расстояние от корня (корень на уровне 0 или 1, в зависимости от соглашения)
- **Глубина узла** — то же, что уровень
- **Путь** — последовательность узлов от одного к другому

**Высота дерева** — длина самого длинного пути от корня до листа (число рёбер). Иногда определяется как число уровней.
- Высота пустого дерева — обычно -1 или 0 (по соглашению)
- Высота дерева из одного узла — 0

**Степень узла** — количество его прямых потомков (детей).
**Степень дерева** — максимальная степень среди всех его узлов.

*Примеры:*
- Бинарное дерево — степень дерева не более 2
- Тернарное — не более 3
- B-дерево порядка m — степень узлов до m

*Пример с высотой:*
```
        A          ← уровень 0
       / \
      B   C        ← уровень 1
     /
    D              ← уровень 2
```
Высота = 2. Степень корня A = 2, степень B = 1, степень C = 0. Степень дерева = 2.

### 2. Способы реализации бинарного дерева. Сравнение

**1. На основе ссылок (узлы с указателями):**
```c
struct Node {
    DataType data;
    Node* left;
    Node* right;
    // опционально: Node* parent;
};
```
- *Плюсы:* естественная структура, динамический размер, эффективная вставка/удаление, подходит для разреженных деревьев.
- *Минусы:* накладные расходы на указатели, плохая кэш-локальность, затраты на аллокацию.

**2. На основе массива (для полных или почти полных деревьев):**
Узлы хранятся в массиве A[0..n-1]:
- Корень в A[0] (или A[1])
- Для узла A[i]: левый потомок — A[2i+1], правый — A[2i+2], родитель — A[(i-1)/2]
- При нумерации с 1: левый — 2i, правый — 2i+1, родитель — i/2

- *Плюсы:* нет указателей — экономия памяти, отличная кэш-локальность, быстрая навигация по индексам, используется в куче (heap).
- *Минусы:* эффективно только для полных или почти полных деревьев; при разреженном дереве — пустые ячейки и расход памяти; сложная вставка/удаление в произвольных позициях.

**3. На основе массива с использованием индексов вместо указателей:**
```c
struct Node {
    DataType data;
    int left_idx;
    int right_idx;
};
Node tree[MAX_SIZE];
```
Промежуточный вариант — есть гибкость и лучшая локальность памяти.

**4. На основе массива с дочерним списком и сиблингом (для деревьев общего вида):**
Каждый узел хранит ссылку на первого потомка и следующего сиблинга.

**Сравнение:**

| Критерий | Указатели | Массив (heap-style) | Индексы |
|---|---|---|---|
| Гибкость | Высокая | Низкая (для полных) | Средняя |
| Память | Больше | Минимум | Средняя |
| Кэш | Плохо | Отлично | Хорошо |
| Вставка/удаление | O(1) после поиска | Сложная | O(1) после поиска |
| Применение | BST, AVL, RB-деревья | Куча, сегментные деревья | Структуры с фикс. размером |

### 3. Способы обхода бинарного дерева

Существуют две основные категории: обход в глубину (DFS) и в ширину (BFS).

**Обходы в глубину (DFS):**

Используется пример дерева:
```
    1
   / \
  2   3
 / \
4   5
```

1. **Прямой обход (Pre-order):** Корень → Левое поддерево → Правое поддерево
   - Результат: **1, 2, 4, 5, 3**
   - Применение: копирование дерева, префиксная запись выражения.

2. **Симметричный обход (In-order):** Левое → Корень → Правое
   - Результат: **4, 2, 5, 1, 3**
   - Применение: для BST даёт отсортированную последовательность.

3. **Обратный обход (Post-order):** Левое → Правое → Корень
   - Результат: **4, 5, 2, 3, 1**
   - Применение: удаление дерева, постфиксная запись выражений.

**Обход в ширину (BFS):**

4. **Уровневый обход (Level-order):** по уровням слева направо
   - Результат: **1, 2, 3, 4, 5**
   - Реализуется через **очередь**.
   - Применение: сериализация дерева, поиск кратчайшего пути.

Все обходы — O(n) по времени. По памяти: DFS — O(h), BFS — O(w), где h — высота, w — максимальная ширина (для сбалансированного дерева w ≈ n/2).

### 4. Что такое дерево поиска?

**Бинарное дерево поиска (BST, Binary Search Tree)** — бинарное дерево, в котором для каждого узла выполняется свойство BST:

> **Все ключи в левом поддереве < ключ узла < все ключи в правом поддереве** (без дубликатов).

Для дубликатов существуют разные соглашения (например, «≤ слева» либо дубликаты не допускаются).

Структура:
```
        8
       / \
      3   10
     / \    \
    1   6    14
       / \   /
      4   7 13
```

**Основные операции:**
- **Search(k):** спуск от корня, сравнение с ключом, поворот налево/направо. Сложность O(h)
- **Insert(k):** спуск, как при поиске, добавление в найденную пустую позицию. O(h)
- **Delete(k):** 3 случая:
  - **Лист** — просто удалить
  - **Один потомок** — заменить узел на потомка
  - **Два потомка** — заменить узел на минимальный в правом поддереве (или максимальный в левом), затем удалить тот
- **Min/Max:** спуск по крайнему левому/правому узлу
- **Successor/Predecessor:** следующий/предыдущий по сортированному обходу

**Важное свойство:** In-order обход BST даёт **отсортированную** последовательность ключей.

### 5. Какова временная сложность алгоритма поиска в дереве поиска?

Поиск элемента в BST спускается по одному пути от корня до искомого узла или до листа.

**Сложность:**
- **Лучший случай:** O(1) — ключ оказался в корне
- **Средний случай** для случайных вставок: O(log n)
- **Худший случай:** O(n) — вырожденное дерево (выглядит как список)

*Пример вырождения:*
Если вставлять отсортированную последовательность 1, 2, 3, 4, 5 в обычное BST, получится:
```
1
 \
  2
   \
    3
     \
      4
       \
        5
```
Здесь высота h = n - 1, и поиск работает за O(n).

В общем случае сложность зависит от **высоты дерева h:** T_search = O(h).

Для **сбалансированных** деревьев (AVL, красно-чёрные, B-деревья) гарантировано h = O(log n), поэтому T_search = O(log n) в худшем случае.

Для случайно построенного BST средняя высота — O(log n), но без гарантий в худшем случае.

### 6. Что такое идеально сбалансированное дерево?

**Идеально сбалансированное бинарное дерево** — дерево, в котором для **каждого** узла количество узлов в его левом и правом поддеревьях отличается **не более чем на 1**.

Эквивалентное определение: дерево, в котором все листья находятся на одном или двух соседних уровнях, и заполнение происходит как можно более полно сверху и слева.

**Свойство:** высота такого дерева — h = ⌊log₂ n⌋.

*Пример* для n = 7 узлов:
```
        4
       / \
      2   6
     / \ / \
    1  3 5  7
```

**Рекурсивный алгоритм построения:**
```
buildTree(n):
    if n == 0: return NULL
    nL = n / 2
    nR = n - nL - 1
    root = createNode(readData())
    root.left = buildTree(nL)
    root.right = buildTree(nR)
    return root
```

**Сравнение со схожими понятиями:**
- **Идеально сбалансированное** — самое строгое условие
- **AVL-сбалансированное** — отличие высот поддеревьев ≤ 1 (более слабое условие)
- **Красно-чёрное** — допускается отличие высот до 2 раз

Идеальная сбалансировка дорого поддерживать — вставка/удаление могут потребовать полной перестройки. Поэтому на практике используются AVL- или RB-деревья: баланс «достаточно хорош», а операции дёшевы.

### 7. Что такое дерево, сбалансированное по АВЛ?

**АВЛ-дерево (AVL-tree)** — бинарное дерево поиска, в котором для **каждого** узла модуль разности высот его левого и правого поддеревьев не превышает 1:

> |h(left) - h(right)| ≤ 1

Это значение |h_L - h_R| называется **balance factor (фактор баланса)** и для корректного АВЛ-узла принимает значения -1, 0, +1.

Названо по именам авторов: советских математиков **Адельсон-Вельского и Ландиса** (1962). Это была первая структура самобалансирующихся BST в истории.

**Свойства:**
- Высота AVL-дерева из n узлов: h ≤ 1.44·log₂(n+2) — то есть O(log n)
- Все операции (поиск, вставка, удаление) — O(log n)
- При вставке/удалении проверяется баланс, при нарушении — выполняются повороты

*Пример AVL-дерева:*
```
        4 (bf=0)
       / \
   2(0)   6(+1)
   / \      \
1(0) 3(0)   7(0)
```

**Различие с идеально сбалансированным:**
- В АВЛ ограничение на **высоты** поддеревьев, в идеально сбалансированном — на **количество** узлов
- АВЛ менее строгое — легче поддерживать на практике

### 8. Какие операции применяют для восстановления сбалансированности дерева?

При нарушении баланса AVL-дерева применяются **повороты (rotations)** — локальные перестройки, сохраняющие свойство BST, но уменьшающие высоту проблемной ветви.

Существует **четыре типа поворотов:**

**1. Малый правый поворот (Right Rotation)** — при «лево-левом» (LL) дисбалансе.

Нарушение: вставка в левое поддерево левого ребёнка.
```
    z              y
   /              / \
  y      →       x   z
 /
x
```

**2. Малый левый поворот (Left Rotation)** — при «право-правом» (RR) дисбалансе.
```
  z                  y
   \                / \
    y      →       z   x
     \
      x
```

**3. Большой правый поворот (Left-Right Rotation)** — при «лево-правом» (LR) дисбалансе.

Нарушение: вставка в правое поддерево левого ребёнка. Сначала левый поворот вокруг y, затем правый поворот вокруг z.
```
    z              z                  x
   /              /                  / \
  y      →      x        →         y   z
   \           /
    x         y
```

**4. Большой левый поворот (Right-Left Rotation)** — при «право-левом» (RL) дисбалансе.

Симметрично: правый поворот вокруг y, затем левый поворот вокруг z.
```
  z              z                    x
   \              \                  / \
    y      →       x          →     z   y
   /                \
  x                  y
```

**Каждый поворот выполняется за O(1).**

**Алгоритм восстановления баланса при вставке:**
1. Спуститься к месту вставки, обновить высоты на обратном пути
2. На каждом узле обратного пути проверять фактор баланса
3. При |bf| > 1 — применить нужный поворот (LL/RR/LR/RL)
4. После одного поворота при вставке баланс восстанавливается полностью (для всего дерева)

При удалении может потребоваться несколько поворотов вверх по пути.

В **красно-чёрных деревьях** используются те же повороты + перекраска узлов — это другой способ поддержания баланса с менее строгими гарантиями высоты, но меньшим количеством поворотов на одну операцию.

## Блок 7. Графы

### 1. Что такое граф?

**Граф** G = (V, E) — математическая структура, состоящая из:
- **V** — конечное множество **вершин (vertices)**
- **E** — множество **рёбер (edges)**, соединяющих пары вершин

**Типы графов:**

*По ориентации:*
- **Неориентированный** — рёбра не имеют направления, {u, v} = {v, u}
- **Ориентированный (digraph)** — рёбра имеют направление, (u, v) ≠ (v, u)

*По весам:*
- **Невзвешенный** — все рёбра равноправны
- **Взвешенный** — каждому ребру сопоставлен вес w(e)

*По наличию специальных рёбер:*
- **Простой** — без петель и кратных рёбер
- **Мультиграф** — допускаются кратные рёбра
- **Псевдограф** — допускаются петли

*По связности:*
- **Связный** — между любыми двумя вершинами есть путь (для ориентированных — сильно связный)
- **Несвязный** — содержит несколько компонент связности
- **Дерево** — связный ациклический неориентированный граф

**Терминология:**
- **Смежные вершины** — соединены ребром
- **Инцидентные** — вершина и её ребро
- **Степень вершины** — количество инцидентных рёбер (для ориентированного: входящая и исходящая)
- **Путь** — последовательность вершин, соединённых рёбрами
- **Цикл** — путь, начинающийся и заканчивающийся в одной вершине

**Применение:**
- Социальные сети (вершины — люди, рёбра — связи)
- Транспортные сети, маршрутизация (GPS)
- Веб-страницы и ссылки (PageRank)
- Зависимости задач (DAG — direct acyclic graph, например, в Makefile)
- Компиляторы (графы потоков управления, графы зависимостей)

### 2. Основные способы реализации графа. Сравнение

**1. Матрица смежности (Adjacency Matrix):**

Двумерный массив A[V][V]:
- A[i][j] = 1 (или вес), если есть ребро i→j
- A[i][j] = 0 (или ∞), если ребра нет

*Пример (неориентированный граф из 4 вершин, рёбра (1,2), (2,3), (3,4)):*
```
   1 2 3 4
1 [0 1 0 0]
2 [1 0 1 0]
3 [0 1 0 1]
4 [0 0 1 0]
```
- *Плюсы:* проверка наличия ребра — O(1), простая реализация, удобно для матричных операций (например, Floyd-Warshall).
- *Минусы:* память O(V²) — расточительна для разреженных графов; перечисление соседей вершины — O(V), даже если их мало.

**2. Список смежности (Adjacency List):**

Для каждой вершины — список (или массив) её соседей.
```
1: [2]
2: [1, 3]
3: [2, 4]
4: [3]
```
- *Плюсы:* память O(V + E) — эффективна для разреженных графов; перечисление соседей — O(deg(v)).
- *Минусы:* проверка наличия ребра — O(deg(v)); хуже кэш-локальность.

**3. Матрица инцидентности (Incidence Matrix):**

Матрица V × E, где I[v][e] = 1, если v инцидентна e (для ориентированных: +1 исходит, -1 входит).
- *Плюсы:* удобна для алгоритмов на рёбрах; можно представить мультиграфы и петли.
- *Минусы:* память O(V·E); редко используется на практике.

**4. Список рёбер (Edge List):**

Просто массив пар (u, v) или троек (u, v, w).
- *Плюсы:* минимум памяти O(E); удобно для алгоритмов, обрабатывающих рёбра подряд (Kruskal, Bellman-Ford).
- *Минусы:* поиск соседей — O(E); проверка ребра — O(E).

**Сравнение:**

| Критерий | Матрица смежности | Список смежности | Список рёбер |
|---|---|---|---|
| Память | O(V²) | O(V+E) | O(E) |
| Проверка ребра | O(1) | O(deg) | O(E) |
| Перебор соседей | O(V) | O(deg) | O(E) |
| Добавление ребра | O(1) | O(1) | O(1) |
| Подходит для | Плотные графы | Разреженные | Простые алгоритмы |

В большинстве задач используется **список смежности**, особенно для разреженных графов (E ≪ V²).

### 3. Алгоритмы обхода графа. Временная сложность

**1. Поиск в глубину (DFS, Depth-First Search):**

Идея: начиная с вершины, идём «в глубину» — переходим к непосещённому соседу, при невозможности возвращаемся назад (backtracking).

Реализация:
- Рекурсивно
- Итеративно через **стек**

```
DFS(v):
    visited[v] = true
    process(v)
    for u in neighbors(v):
        if not visited[u]:
            DFS(u)
```

**Сложность: O(V + E)** при списке смежности, O(V²) при матрице.

**Память:** O(V) — стек рекурсии.

**Применение:**
- Поиск компонент связности
- Топологическая сортировка
- Поиск циклов
- Поиск мостов и точек сочленения
- Поиск компонент сильной связности (алгоритмы Тарьяна, Косарайю)

**2. Поиск в ширину (BFS, Breadth-First Search):**

Идея: посещаем все вершины на расстоянии k, потом на расстоянии k+1.

Реализация через **очередь:**
```
BFS(s):
    visited[s] = true
    queue.push(s)
    while not queue.empty():
        v = queue.pop()
        process(v)
        for u in neighbors(v):
            if not visited[u]:
                visited[u] = true
                queue.push(u)
```

**Сложность: O(V + E)** при списке смежности.

**Память:** O(V) — очередь.

**Применение:**
- Кратчайший путь в **невзвешенном** графе
- Поиск компонент связности
- Проверка двудольности графа
- Алгоритм Эдмондса-Карпа (максимальный поток)
- Распространение в социальных сетях

**Сравнение DFS и BFS:**

| Критерий | DFS | BFS |
|---|---|---|
| Структура | Стек (или рекурсия) | Очередь |
| Порядок обхода | Вглубь, потом вширь | По уровням |
| Память | O(V) | O(V), хуже на «широких» графах |
| Кратчайший путь | Не гарантирует | Гарантирует в невзвешенном |
| Топологическая сортировка | Да | Нет (без модификаций) |

### 4. Алгоритмы нахождения кратчайшего пути в графе

**1. BFS (для невзвешенных графов):**
- Кратчайший путь по числу рёбер
- Сложность: **O(V + E)**

**2. Алгоритм Дейкстры (Dijkstra):**
- Кратчайший путь от одной вершины до всех (single-source shortest paths)
- Веса рёбер должны быть **неотрицательными**
- Идея: жадно выбираем непосещённую вершину с минимальным расстоянием, релаксируем её соседей

Сложность:
- С простым массивом: O(V²)
- С двоичной кучей (priority queue): **O((V + E) log V)**
- С фибоначчиевой кучей: O(E + V log V)

Применение: GPS-навигация, маршрутизация сетей.

**3. Алгоритм Беллмана-Форда (Bellman-Ford):**
- От одной вершины до всех
- Допускает **отрицательные** веса (но не отрицательные циклы)
- Идея: V-1 раз релаксировать все рёбра

Сложность: **O(V·E)**

Применение: маршрутизация в сетях (RIP), обнаружение отрицательных циклов.

**4. Алгоритм Флойда-Уоршелла (Floyd-Warshall):**
- Между **всеми парами** вершин (all-pairs shortest paths)
- Допускает отрицательные веса (без отрицательных циклов)
- Динамическое программирование: рассматриваем, можно ли улучшить путь, проходя через вершину k

Сложность: **O(V³)**, память O(V²).

Применение: транзитивное замыкание, малые плотные графы.

**5. Алгоритм Джонсона (Johnson):**
- Между всеми парами вершин
- Допускает отрицательные веса
- Комбинация Bellman-Ford + перевзвешивание + Dijkstra от каждой вершины

Сложность: **O(V² log V + V·E)** — лучше Floyd-Warshall на разреженных графах.

**Сравнение:**

| Алгоритм | Тип | Веса | Сложность |
|---|---|---|---|
| BFS | One-to-all | Невзвешенный | O(V+E) |
| Dijkstra | One-to-all | ≥ 0 | O((V+E) log V) |
| Bellman-Ford | One-to-all | Любые | O(V·E) |
| Floyd-Warshall | All-pairs | Любые | O(V³) |
| Johnson | All-pairs | Любые | O(V² log V + V·E) |

### 5. Переборные алгоритмы нахождения кратчайшего пути в графе

Переборные (brute-force) алгоритмы рассматривают все возможные пути или их значительную часть. Применяются для задач, где жадные/динамические подходы неприменимы или недостаточны.

**1. Полный перебор путей (Naive backtracking):**
Перебираем все возможные пути от s до t рекурсивным DFS с возвратом.
- Сложность: до **O(V!)** в худшем случае (все перестановки вершин).

**2. Перебор с отсечением (Branch and Bound):**
Перебор + отсечение бесперспективных ветвей: если текущая длина пути уже больше известного минимума — не продолжаем.
- Сложность: формально экспоненциальная, но на практике значительно быстрее.

**3. A\* (A-star):**
Эвристический алгоритм перебора с оценкой f(n) = g(n) + h(n):
- g(n) — стоимость пути от старта до n
- h(n) — эвристическая оценка от n до цели

При **допустимой** эвристике (h не переоценивает) гарантируется оптимальное решение.

- Сложность: зависит от эвристики, в худшем — экспоненциальная, на практике часто быстрее Dijkstra.
- Применение: игры, робототехника, навигация.

**4. IDA\* (Iterative Deepening A\*):**
Итеративное углубление с эвристикой. Память O(V), вместо O(V²) у A*.

**5. Задача коммивояжёра (TSP)** — кратчайший путь, посещающий все вершины:
- Полный перебор: O(n!)
- ДП Хелда-Карпа: O(2ⁿ · n²) — экспоненциально, но лучше O(n!)
- Эвристики и метаэвристики (генетические, муравьиные алгоритмы) — приближённые решения

**Когда применяют переборные алгоритмы:**
- Граф очень мал
- Требуется глобальный оптимум для NP-трудной задачи
- Жадные методы не дают оптимума
- Задачи с дополнительными ограничениями (TSP, задача о рюкзаке, маршруты с препятствиями)

### 6. Алгоритмы нахождения минимального остовного дерева графа

**Минимальное остовное дерево (Minimum Spanning Tree, MST)** — подмножество рёбер связного взвешенного неориентированного графа, образующее дерево, соединяющее все вершины с минимальной суммой весов.

**Свойства MST:**
- Содержит ровно V − 1 ребро
- Не имеет циклов
- Связно
- Сумма весов минимальна

**1. Алгоритм Прима (Prim):**

Идея: начинаем с произвольной вершины, на каждом шаге добавляем минимальное ребро, соединяющее уже включённую вершину с не включённой («жадно растим дерево»).

Сложность:
- С массивом: O(V²)
- С двоичной кучей: O((V + E) log V) = O(E log V)
- С фибоначчиевой кучей: O(E + V log V)

Лучше подходит для **плотных** графов.

**2. Алгоритм Краскала (Kruskal):**

Идея: сортируем все рёбра по весу. Идём по возрастанию, добавляем ребро, если оно не образует цикл (проверка через DSU — Disjoint Set Union, систему непересекающихся множеств).

Сложность: **O(E log E) = O(E log V)** (сортировка + DSU с почти-константной α-функцией обратной Аккермана).

Лучше подходит для **разреженных** графов.

**3. Алгоритм Борувки (Borůvka):**

Идея: на каждом шаге для каждой компоненты выбирается минимальное исходящее ребро, все они добавляются одновременно. Компоненты объединяются.

Сложность: **O(E log V)**. Хорошо параллелизуется. Исторически — самый ранний алгоритм MST (1926).

**4. Алгоритм Чазелла:**

Использует мягкие кучи (soft heaps). Сложность близка к линейной: O(E · α(V, E)). Сложен в реализации, представляет в основном теоретический интерес.

**Сравнение:**

| Алгоритм | Сложность | Структура | Лучше для |
|---|---|---|---|
| Прим (массив) | O(V²) | Массив | Плотные графы |
| Прим (куча) | O(E log V) | Priority queue | Средние графы |
| Краскал | O(E log V) | Sort + DSU | Разреженные графы |
| Борувка | O(E log V) | Несколько кругов | Параллельные системы |

**Применение MST:**
- Проектирование сетей (электрических, телефонных, компьютерных) с минимальной стоимостью прокладки
- Кластеризация (single-linkage clustering)
- Алгоритмы аппроксимации (например, 2-приближение TSP через двойной обход MST)
- Сетевые протоколы (Spanning Tree Protocol в Ethernet — для предотвращения петель)
