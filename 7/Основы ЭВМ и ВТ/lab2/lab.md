## Задание

Реализовать на языке ассемблера ARM алгоритм целочисленной операции, разработанный в лабораторной работе №1, с учётом дополнительной функции. Выбрать места хранения данных, перевести блоки алгоритма в команды ARM, отладить программу в ARMSim# и представить результаты вычислений.

В соответствии с заданием ЛР1 для номера по журналу 11:

- Номер алгоритма: `11 mod 16 + 1 = 12`.
- Номер дополнительной функции: `11 mod 10 + 1 = 2`.
- Число информационных разрядов операндов: `11 mod 6 + 4 = 9`.
- Полная разрядность каждого операнда с учётом знака: `9 + 1 = 10` бит.

**Алгоритм №12:** умножение целых чисел со знаком в дополнительном коде с неподвижной суммой частичных произведений, сдвигом множимого влево и анализом множителя начиная с младших разрядов, с предварительным изменением знака.

**Дополнительная функция №2:** переместить три младших разряда результата в другой регистр, оставшиеся разряды не перемещать. Как в ЛР1, это реализуется копированием `R := P AND 7` с сохранением исходного `P`.

Основной пример: `X = 13`, `Y = −7`. Ожидается `P = −91`, `R = 5 = 101₂`.

## 1. Список переменных и размещение данных

Рабочие переменные размещены в регистрах общего назначения, исходные числа и окончательные результаты — также в памяти. Регистры ARM имеют разрядность 32 бита. Отрицательные числа загружаются в дополнительном коде со знаковым расширением.

| Переменная | Назначение | Размещение |
|---|---|---|
| X, Y | Исходное множимое и множитель | `inputs`, при вычислении `r0`, `r1` |
| S | Сумма частичных произведений | `r2` |
| M | Рабочее множимое, сдвигаемое влево | `r3` |
| Q | Неотрицательный рабочий множитель | `r4` |
| i | Число обработанных разрядов, 0…9 | `r5` |
| P | Произведение | `r6` и первое слово `results` |
| R | Три младших бита произведения | `r7` и второе слово `results` |
| — | Указатель чтения исходных данных | `r8` |
| — | Указатель записи результатов | `r9` |

После вычисления `r0` и `r1` используются для параметров вывода. Значения `P` и `R` сохраняются в `r6`, `r7` и памяти. Трёхразрядный регистр из ЛР1 моделируется младшими тремя битами 32-разрядного `r7`; его старшие биты равны нулю.

В ЛР1 результат изображался 20-разрядным словом. Здесь он хранится в 32 битах. Для выбранных операндов переполнения нет; младшие 20 бит совпадают с представлением ЛР1.

## 2. Блок-схема алгоритма

![Блок-схема алгоритма №12 с дополнительной функцией №2](algorithm.png)

*Рисунок 1 — Алгоритм умножения с предварительным изменением знаков операндов и выделением трёх младших разрядов результата.*

Схема построена в PlantUML; исходный файл — algorithm.puml.

Если `Y < 0`, оба операнда меняют знак. Равенство `X · Y = (−X) · (−Y)` сохраняет произведение. После этого `S = 0`, `M = X`, `Q = Y`, `i = 0`.

На каждой из девяти итераций проверяется младший бит `Q`. Если он равен единице, выполняется `S := S + M`. Затем `M` сдвигается влево, `Q` — логически вправо, а счётчик увеличивается. По окончании цикла выполняются `P := S` и `R := P AND 7`.

Для сохранённого из ЛР1 цикла из 9 итераций требуется `|Y| ≤ 511`. Граничное значение 10-разрядного дополнительного кода `Y = −512` требует отдельной обработки или десятой итерации. Все выбранные примеры находятся в допустимой области алгоритма ЛР1.

## 3. Код программы на языке ассемблера ARM

Основная программа приведена ниже. Исходный файл — lab2.s.

```asm
@ Lab 2. Journal 11; algorithm 12; function 2; n = 9.
@ Main example: 13 * (-7) = -91; low three bits = 5.
        .text
        .global _start
_start:
        LDR r8, =inputs
        LDR r9, =results
        LDR r0, [r8], #4
        LDR r1, [r8], #4
        CMP r1, #0
        BGE init
        RSB r0, r0, #0
        RSB r1, r1, #0
init:
        MOV r2, #0
        MOV r3, r0
        MOV r4, r1
        MOV r5, #0
multiply_loop:
        CMP r5, #9
        BGE finish_product
        TST r4, #1
        BEQ shift
        ADD r2, r2, r3
shift:
        MOV r3, r3, LSL #1
        MOV r4, r4, LSR #1
        ADD r5, r5, #1
        B multiply_loop
finish_product:
        MOV r6, r2
        AND r7, r6, #7
        STR r6, [r9], #4
        STR r7, [r9], #4
        LDR r0, =label_p
        SWI 0x02
        MOV r0, #1
        MOV r1, r6
        SWI 0x6b
        LDR r0, =label_r
        SWI 0x02
        MOV r0, #1
        MOV r1, r7
        SWI 0x6b
        MOV r0, #10
        SWI 0x00
        SWI 0x11
        .data
        .align 2
inputs:
        .word 13, -7
results:
        .word 0, 0
label_p:
        .asciz "P = "
label_r:
        .asciz "; R = "
        .end
```

### Соответствие блоков схемы командам

| Блок алгоритма | Реализация |
|---|---|
| Загрузка X, Y | `LDR` загружает адреса, затем значения слов памяти |
| Проверка Y < 0 | `CMP r1, #0`; знаковый переход `BGE init` |
| Изменение знаков | `RSB r0, r0, #0`; `RSB r1, r1, #0` |
| Инициализация S, M, Q, i | Четыре команды `MOV` после метки `init` |
| Проверка i < 9 | `CMP r5, #9`; `BGE finish_product` |
| Проверка младшего бита | `TST r4, #1`; `BEQ shift` при нулевом бите |
| Сложение S + M | `ADD r2, r2, r3` |
| Сдвиги и счётчик | `MOV` с `LSL #1`, `MOV` с `LSR #1`, `ADD r5, r5, #1` |
| Сохранение P | `MOV r6, r2` |
| Дополнительная функция | `AND r7, r6, #7`, маска `7 = 111₂` |
| Запись результатов | Две команды `STR` |
| Вывод и завершение | Сервисы `SWI` симулятора |

Команда `TST` вычисляет логическое И для установки флагов, не изменяя операнды. `BEQ` выполняет переход при `Z = 1`. Команда `RSB` с нулём вычисляет отрицание операнда. `MOV` со сдвигом позволяет использовать сдвиговый механизм ARM. Команда аппаратного умножения `MUL` не применяется.

При адресации `[r8], #4` или `[r9], #4` сначала используется текущий адрес, затем указатель увеличивается на 4 байта. Директива `.word` задаёт 32-разрядные слова, `.asciz` — строку с завершающим нулём. `.end` завершает исходный текст; остановку выполнения обеспечивает `SWI 0x11`.

Сервисы ARMSim# 1.91: `SWI 0x02` выводит строку по адресу в `r0`; `SWI 0x6B` выводит целое число из `r1` при `r0 = 1`; `SWI 0x00` выводит символ из `r0`. Значение 10 соответствует переводу строки.

## 4. Карта распределения памяти

Адреса определены по листингу ARMSim# 1.91 для приведённой программы. В памяти используются 32-разрядные слова по 4 байта. Регистры процессора собственных адресов в этой карте не имеют.

| Диапазон адресов | Размер, байт | Назначение |
|---|---:|---|
| `0x1000–0x100F` | 16 | Загрузка указателей и операндов |
| `0x1010–0x101F` | 16 | Проверка и предварительное изменение знаков |
| `0x1020–0x102F` | 16 | Инициализация S, M, Q, i |
| `0x1030–0x1053` | 36 | Цикл обработки разрядов |
| `0x1054–0x1063` | 16 | Формирование P, R и запись результатов |
| `0x1064–0x1097` | 52 | Вывод и остановка программы |
| `0x1098–0x10A7` | 16 | Пул литералов: адреса меток для `LDR reg, =label` |
| `0x10A8–0x10AF` | 8 | Исходные операнды `inputs` |
| `0x10B0–0x10B7` | 8 | Результаты `results` |
| `0x10B8–0x10BC` | 5 | Строка `P = ` и нулевой байт |
| `0x10BD–0x10C3` | 7 | Строка `; R = ` и нулевой байт |

Исполняемый код занимает 152 байта: 38 команд по 4 байта. Код, пул литералов и данные занимают вместе 196 байт (`0xC4`). Стек и динамическая память в программе не используются.

| Адрес слова | Содержимое | До запуска | После запуска |
|---|---|---|---|
| `0x10A8` | X | `13 = 0x0000000D` | Без изменения |
| `0x10AC` | Y | `−7 = 0xFFFFFFF9` | Без изменения |
| `0x10B0` | P | `0` | `−91 = 0xFFFFFFA5` |
| `0x10B4` | R | `0` | `5 = 0x00000005` |

Пул литералов содержит `0x10A8` по адресу `0x1098`, `0x10B0` по `0x109C`, `0x10B8` по `0x10A0` и `0x10BD` по `0x10A4`. Эти слова создаются ассемблером для загрузки адресов меток.
